# Question Bank Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Questions live in one JSON file per subject, labelled with language, topics, difficulty
and references; a build turns them into the JS file the game loads; the game spreads subjects and
topics and asks at most two Catalan questions; the bank grows from 30 to about 60.

**Architecture:** `questions/<subject>.json` files hold each subject's topics and questions.
`scripts/build-questions.js` validates them and writes `js/questions.js` (committed, defines
`APN.TOPICS` and `APN.QUESTIONS`); a unit test fails when that file is stale. `APN.pickQuestions`
gains three preference rules with a fixed relaxing order. `js/ui.js` marks each question's
language on screen.

**Tech Stack:** Plain JavaScript (no build for the game, no dependency), Node 24 `node:test`,
Playwright, GitHub Actions.

**Spec:** `docs/specs/2026-11-18-question-bank-design.md`

## Global Constraints

- No new dependency; `index.html` opened from disk keeps working with no build step.
- Code, identifiers, file names, test names and comments in English; text the player reads in
  Spanish, except a question's own text, which is in its `lang`.
- Subjects, in this order: `geography`, `history`, `sports`, `culture`, `maths`, `science`,
  `language`, `english`, `catalan`.
- Languages: `es`, `ca`, `en`. `english` ⇔ `en`; `catalan` ⇒ `ca`; `language` ⇒ `es`; any other
  subject is `es` or `ca`.
- Question fields, exactly these, in this order in the JSON: `id`, `lang`, `topics`, `difficulty`,
  `place`, `minAge`, `maxAge`, `prompt`, `options`, `correct`, `explanation`, `references`. In the
  generated file `subject` is inserted after `lang`.
- Topic fields: `id`, `name` in the JSON; `id`, `subject`, `name` in `APN.TOPICS`.
- Limits: `prompt` ≤ 120 characters, each option ≤ 40, `explanation` ≤ 160; 4 distinct non-blank
  options; `correct` integer 0–3; `difficulty` 1, 2 or 3; 1 to 3 distinct topics; `minAge` 10,
  `maxAge` 12; at least one reference starting with `https://`.
- Ids (questions and topics): lowercase letters, digits and hyphens (`/^[a-z0-9]+(-[a-z0-9]+)*$/`),
  unique across all files.
- Place questions only in `geography`, `history`, `sports`, `culture`.
- At most 2 `ca` questions per game.
- Every question in the project's own words; no text copied or adapted from XTEC or any source.
- Generated file header, first line: `// Generated by scripts/build-questions.js from questions/*.json. Do not edit by hand.`
- Problem line format: `<file>: <id>: <problem>`; file-level problems use `-` as the id.
- Never write the owner's name in repository files.

## Review Focus

1. **A JSON file with a syntax error** (a trailing comma from a hand edit): the build must report
   `<file>: -: invalid JSON` and exit 1, not crash with a stack trace. Test in Task 1.
2. **Accented and special characters** (`à`, `ç`, `l·l`, `«»`, `ñ`, `'`): must survive the round
   trip JSON → `js/questions.js` → screen unchanged, and the stale-file test must stay stable.
   Test in Task 2 (`accented text survives the build`).
3. **A Catalan-heavy bank:** after future batches most new questions may be Catalan; the cap must
   still hold. Test in Task 3 (many seeds over a bank where 80 % of candidates are Catalan).
4. **The explanation after a wrong answer** is shown in a notice next to Spanish text: only the
   explanation line carries the question's `lang`. Test in Task 4.
5. **A question whose topic was renamed in its file** but not in the question: build error
   `unknown topic`, not a silent pass. Test in Task 1.

### Task 1: The build script

**Files:**
- Create: `scripts/build-questions.js`
- Test: `tests/build-questions.test.js`

**Interfaces:**
- Consumes: `js/data-level-1.js` (`APN.SUBJECTS`, `APN.LEVELS[0].stops[].id`), only in `main`.
- Produces:
  - `validateBank(files, context) -> string[]` — `files`: `Array<{ file: string, data: unknown }>`
    where `file` is the base name (`maths.json`) and `data` the parsed JSON or the symbol
    `INVALID_JSON`; `context`: `{ subjects: string[], stopIds: string[] }`. Returns problem lines,
    empty when valid.
  - `renderQuestionsJs(files, subjects) -> string` — the full text of `js/questions.js` for a valid
    bank; files in `subjects` order, questions in file order, keys reordered per Global
    Constraints, `JSON.stringify(value, null, 2)`, trailing newline.
  - `buildQuestions(dir, context) -> { problems: string[], output: string | null }` — reads
    `<dir>/*.json`, parses each (a parse failure becomes `INVALID_JSON`), validates, renders.
  - `INVALID_JSON` (exported symbol).
  - `main()` when run directly: builds from `questions/`, writes `js/questions.js` on success;
    otherwise prints the problems to stderr, writes nothing, exits 1.
  - Module exports `{ validateBank, renderQuestionsJs, buildQuestions, INVALID_JSON }`, guarded by
    `require.main === module` like `scripts/stamp-release.js`.
- `package.json` script: `"build:questions": "node scripts/build-questions.js"`.
- `APN.SUBJECTS` in `js/data-level-1.js` gains `'catalan'` at the end.

Problem texts (exact):

| Condition | Line |
|---|---|
| unparseable file | `<file>: -: invalid JSON` |
| file not `{ topics: [], questions: [] }` | `<file>: -: must be an object with "topics" and "questions" arrays` |
| file name not a subject | `<file>: -: not a subject` |
| subject with no file | `<subject>.json: -: missing file` |
| bad or duplicate topic id | `<file>: -: invalid topic id "<id>"` / `<file>: -: duplicate topic id "<id>"` |
| bad id format | `<file>: <id>: invalid id` |
| duplicate question id | `<file>: <id>: duplicate id` |
| missing / unknown field | `<file>: <id>: missing field "<f>"` / `<file>: <id>: unknown field "<f>"` |
| language | `<file>: <id>: language "<lang>" does not match subject "<subject>"` |
| topics count or repeats | `<file>: <id>: needs 1 to 3 different topics` |
| topic not in the same file | `<file>: <id>: unknown topic "<t>"` |
| difficulty | `<file>: <id>: difficulty must be 1, 2 or 3` |
| place | `<file>: <id>: unknown place "<p>"` |
| place in a non-place subject | `<file>: <id>: a question about a place must be geography, history, sports or culture` |
| ages | `<file>: <id>: ages must be 10 to 12` |
| options | `<file>: <id>: needs 4 different non-blank options` |
| correct | `<file>: <id>: correct must be 0 to 3` |
| lengths | `<file>: <id>: prompt longer than 120 characters` / `option longer than 40 characters` / `explanation longer than 160 characters` |
| references | `<file>: <id>: needs at least one https reference` |

A question with no usable `id` uses `?` as its id in the line.

### Task 3: The picker spreads subjects and topics and caps Catalan

**Files:**
- Modify: `js/game-logic.js` (`APN.pickQuestions`)
- Test: `tests/game-logic.test.js`

**Interfaces:**
- Consumes: questions with `lang`, `subject`, `topics`.
- Produces: `APN.pickQuestions(level, bank, age, rng) -> Question[]`, same signature and same
  alternation as today; the existing tests keep passing.

Rules for each turn, among that turn's candidates (place or general, general never twice):
1. no more than two `ca` questions in the game;
2. a subject not yet used in the game;
3. no topic shared with a question already picked.
Pick at random among candidates meeting all three; if none, drop rule 3, then rule 2, then
rule 1; an empty candidate list throws `Not enough questions for this level and age`.

- [ ] **Step 1: Write the failing tests** (a local `seededRng(seed)` helper, e.g. mulberry32, for
  many-seed tests; fixture banks built in the test):
  - `a game never has more than two Catalan questions` — bank where 80 % of each turn's
    candidates are `ca`; 200 seeds; every game has ≤ 2 `ca`.
  - `a game spreads subjects when the bank allows it` — bank where each turn has candidates of
    every subject; 200 seeds; six different subjects each game.
  - `a game avoids shared topics when the bank allows it` — 200 seeds; no topic appears twice.
  - `the Catalan cap outlasts the subject and topic rules` — a bank where the only non-Catalan
    candidate of a turn repeats a subject and a topic already used; the game still has ≤ 2 `ca`.
  - `the rules are relaxed rather than failing` — every candidate `ca`, one subject, one topic:
    six questions returned.
- [ ] **Step 2: Run** `node --test tests/game-logic.test.js` — expected: the cap, spread and
  topic tests FAIL; the relaxed test may pass.

- [ ] **Step 4: Run** `npm test` and `npx playwright test` — expected: all PASS.

### Content review (after Task 5, before the whole-branch review)

A fresh reviewer, separate from the code review, checks every new or relabelled question: the
fact against its reference (opening it), Catalan and Spanish spelling, the own-words rule (no
sentence matching the reference's text), the difficulty label against the scale, the language
and subject agreement, and that the wrong options are plausible but clearly wrong. It reports
per question id; fixes go to a fresh implementer.
